v3.9.2 管理端穩定重建版
========================

這一包不是在舊 v3.9.x 上繼續疊補丁，而是固定回到 v3.9.2 版本號，重新整理管理端與讀取架構。

【管理端主選單只有 6 個】
1. 會員列表
2. 新增會員
3. 客訂商品
4. 統計報表
5. 店員管理
6. 系統設定

已取消：首頁、會員管理獨立入口、新增消費獨立入口、消費紀錄獨立入口、商品管理、庫存管理。
新增消費、消費紀錄、會員資料、點數紀錄仍保留在「會員列表 → 點開會員」裡。

【這版為什麼比較穩】
- 登入後管理員權限：直接檢查 admins 資料表
- 會員列表：直接讀 members
- 會員詳細：直接讀 members + transactions
- 客訂：直接讀寫 custom_orders
- 店員：直接讀寫 staff_options
- 統計報表：由伺服器讀 transactions 後計算，不依賴 v3.9 報表 RPC
- 系統健康檢查、備份：直接讀資料表
- 點數紀錄：由交易紀錄重建顯示，不依賴 admin_operations_v3 的 ledger
- 只有「新增消費 / 作廢 / 編輯交易品項」保留既有 admin_write_v2 RPC，因為這些動作需要資料庫原子交易才能避免點數錯帳。

【SQL 請執行哪一個】
請在 Supabase SQL Editor 執行：
  sql/09_upgrade_v3_9_2_rebuild.sql

這支 SQL 可以重複執行，不會刪除：
- 會員
- 消費紀錄
- 點數
- 客訂資料

它只確認客訂 / 店員資料表存在，並補上客訂備註欄位。

如果你之前已經執行過舊版 08 / 09 / 10，也可以直接執行這支新版 09；
舊的 v3.9 RPC 即使還存在，本版管理端主要讀取也不會再依賴它們。

【部署順序】
1. Supabase 執行 sql/09_upgrade_v3_9_2_rebuild.sql
2. Vercel 部署這整包程式
3. 確認環境變數：
   SUPABASE_URL
   SUPABASE_SECRET_KEY
   SUPABASE_PUBLISHABLE_KEY
   LINE_CHANNEL_ID
   LIFF_ID
   STORE_NAME
4. 若要用客訂 LINE 一鍵通知，再設定：
   LINE_CHANNEL_ACCESS_TOKEN
5. 部署完成後，用無痕視窗開 /admin.html 登入測試，避免舊 JS 快取。
